💧 WellWatch AI
Desert Water Source Early-Warning System
WellWatch AI is a prototype dashboard designed to demonstrate how water-source monitoring data can be organized into useful trends, forecasts, sensor-health checks, and early-warning indicators.
Prototype disclosure: This project currently uses simulated well-monitoring data. Its predictions and alert thresholds are experimental and are not verified real-world failure warnings. It is not connected to live sensors, satellite feeds, or an operational SMS service.

Problem
Water sources in arid regions can face changing water levels and salinity. When monitoring information is fragmented or difficult to interpret, it can be harder to notice concerning trends early.
Proposed solution
WellWatch AI brings several monitoring tasks into one interactive dashboard:
- Overview of selected wells and their current risk labels
- Historical water-depth trends
- Short-term depth forecasts
- Forecast error information based on a chronological validation split
- Sensor-health status and a simulated sensor-failure demonstration
- Alert/report tables and downloadable data
Main features
1. Interactive overview: filter wells and risk categories to focus the dashboard.
2. Well analysis: inspect a selected well, zoom the historical date range, and choose a forecast horizon.
3. Forecasting: a simple linear-regression baseline estimates future water depth from elapsed time.
4. Risk indicators: demonstration rules combine recent depth and salinity trends into LOW, WATCH, or HIGH labels.
5. Sensor health: highlights sensor data-quality issues; the demo can simulate a stale sensor.
6. Exports: download available tables for offline review.

Setup on Windows
1. Install Python 3.10 or later.
2. Download or clone this repository.
3. Open the project folder in VS Code.
4. Open the VS Code terminal (PowerShell).
5. Create a virtual environment: python -m venv .venv
6. Activate it: .\venv\Scripts\Activate.ps1
7. Install dependencies: python -m pip install -r requirements.txt
8. Start the dashboard: python -m streamlit run app.py
9. Open the local URL printed in the terminal (usually http://localhost:8501).
If PowerShell blocks activation, run this for the current terminal session:
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
Then activate the environment again.
Data and modelling workflow
1. generate_data.py creates the demonstration dataset (if included and used).
2. inspect_data.py checks dataset shape, data types, missing values, duplicates, and summary statistics.
3. clean_data.py parses dates, sorts records, handles duplicates/missing values, and creates derived fields.
4. visualize_data.py produces exploratory trend plots.
5. forecast_model.py trains and evaluates a per-well linear-regression baseline and writes forecast outputs.
6. alert_engine.py calculates demonstration risk labels from recent depth and salinity trends.
7. sensor_health.py produces sensor-health status for the dashboard.
Run only the scripts that are present and required by your final app. Keep the CSV filenames consistent with the filenames referenced in app.py.
Understanding the forecast
The baseline model uses elapsed day number as its predictor and water depth as its target. Historical data is split chronologically for a simple holdout evaluation, then the model is refit on the available history to produce future estimates.

Metrics such as MAE and RMSE describe errors on the held-out portion of this simulated dataset. A reported percentile of absolute error is a historical error summary; it is not a statistically calibrated confidence interval and should not be described as a guaranteed prediction range.
Understanding the risk labels
The LOW / WATCH / HIGH labels are generated by demonstration rules using recent depth and salinity trends. The thresholds are illustrative and have not been validated against local hydrogeological expertise, official standards, or operational well records.
Sensor-health demonstration
The sensor-health section demonstrates the importance of data reliability. Treat a stale or missing reading as a data-quality warning. In this prototype, a sensor-health warning does not itself prove that a well is failing and should not be confused with the separate trend-based risk label.
Limitations
- Data is simulated, not collected from real wells.
- Forecasting is a simple baseline and currently uses elapsed time rather than all potentially relevant factors such as rainfall, pumping, temperature, and salinity.
- Validation results on synthetic data do not establish real-world predictive accuracy.
- Alert thresholds are demonstration values, not validated operational thresholds.
- Any map coordinates shown in the demo are illustrative, not verified well locations.
- Downloadable alert text is not the same as sending SMS notifications.
- This prototype is for demonstration and educational purposes, not operational water-management decisions.
Future improvements
- Integrate authenticated live sensor feeds and reliable data ingestion.
- Validate the model on representative historical well data.
- Include pumping, rainfall, temperature, geology, and seasonal effects where appropriate.
- Work with domain experts to establish and validate alert thresholds.
- Add calibrated uncertainty estimates and monitoring for model drift.
- Add role-based access, audit logs, secure hosting, and tested notification delivery.
- Replace illustrative map points with verified, permissioned locations.
